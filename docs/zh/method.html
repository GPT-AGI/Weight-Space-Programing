规则与方法

同一套工具，精确真值。

WSP-Bench 衡量大模型在看不到干净检查点的条件下，排查并修复受控权重缺陷的能力。

任务类型

行为植入

通过秩 1 编辑诱导语言切换、全大写、复读等可测行为；修复缺陷，同时控制副作用。

触发器后门

未知触发词会激活秩 1 key→value 编辑；找出触发条件并清除后门。

定位审计

网络某处被植入编辑；不修改权重，只报告层、参数和方向。

神经元劫持

少量被放大的神经元让某个 Token 刷屏；将输出恢复正常。

评分

编辑类任务在隐藏提示集上衡量修复率，并按通用留出文本上的副作用扣分；各项均截断到规定范围。

repair = clip((bug_rate(broken) − bug_rate(submitted)) / (bug_rate(broken) − bug_rate(clean)), 0, 1)
instance_score = 100 × repair × (1 − collateral_penalty)

副作用惩罚由逐 Token 平均 KL(clean ∥ submitted) 计算，免罚与满罚阈值在评测前冻结。审计任务使用 100 × localization，综合层/参数定位和报告方向与真值方向的绝对余弦相似度。总分为实例平均分，并对实例做 bootstrap 得到 95% 置信区间。

公平性与防泄漏

  • 所有模型使用相同的 system prompt、文本协议、轮数上限、GPU 调用上限、编辑预算和美元上限。
  • Python 沙箱断网，且只包含坏模型；干净检查点和真值仅存在于评分进程。
  • 缺陷方向、强度、层号和触发词均随机生成；正式 test 规格与种子不公开。
  • 行为指标全部由规则计算，不使用 LLM 裁判。
  • 每次运行都记录模型 ID、供应商设置、Token、美元成本、GPU 调用、停止原因和完整轨迹。

预算

v0.1 每个实例最多 40 轮、20 次 GPU 调用，batch 上限 64，单次生成最多 128 个新 Token，最多改动 262,144 个参数，模型 API 成本上限 $1.50。触及任一上限后停止，并按当前提交评分。

参照行

  • Oracle（100）：知道植入编辑并直接逆转。
  • No-op（0）：不做任何修改，直接提交坏模型。
  • 固定脚本：不使用 LLM 的固定可解释性流程。它与各 LLM 的分差，是衡量 LLM 额外贡献的直接参照。

如何解读

这些合成缺陷用于实现精确评分。高分证明模型擅长执行给定实验闭环，但不能证明它能仅凭原始权重推断任意神经网络的用途。
